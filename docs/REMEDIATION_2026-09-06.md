## 검증 및 동작상 유의점

- `go test ./...`, `go vet ./...`, `go test -race ./...`: 모두 통과.
- 설치된 FFmpeg로 영상+220Hz 음성 입력과 별도 880Hz 음성 입력을 생성하여, 병합 결과가 별도 음성을 선택했음을 PCM으로 검사했다. 실제 FFmpeg의 잘못된 muxer 조합 실패에서도 이전 정상 출력이 보존됨을 검사했다.
- gopls MCP를 호출했으나 새 파일 `internal/httpx/rate.go` 등을 기존 workspace snapshot에 반영하지 못해 미정의 심볼 진단을 반환했다. 이를 정상 진단으로 간주하지 않았으며 실제 Go 컴파일·vet·race 결과로 검증했다. MCP 재연결 후 새 파일을 포함한 LSP 진단을 다시 확인할 수 있다.
- 취소된 라이브 트랙은 보존하며 취소된 context로 자동 병합하지 않는다. 보존 파일의 후속 병합은 별도 작업이다.
- SegmentList/SegmentBase 및 DRM은 구현 지원을 추가한 것이 아니라 잘못된 정상 다운로드를 명시적인 오류로 바꾼 것이다.
- `.ytv1-lock`은 ytv1 프로세스 간 동시 출력을 막는다. 비정상 프로세스 종료로 잠금 디렉터리가 남으면 소유 프로세스가 종료되었음을 확인한 뒤 제거해야 한다. 외부 프로그램의 파일 쓰기까지 제어하는 잠금은 아니다.
- 아카이브 Has/Add는 신규 완료 기록을 관측하지만 다운로드 전체의 예약 트랜잭션은 아니다. 같은 출력의 동시 쓰기는 별도 출력 잠금이 막는다.
- 원격 SOOP 장시간 재접속과 실제 CDN window 변경은 이 로컬 검증에 포함하지 않았다. 해당 환경에서 새 매체 URL·에이전트 연결로 실행할 외부 검증 항목으로 유지한다. 로컬 가용 구간·취소·헤더 보존·오류 전달은 자동 검사했다.
